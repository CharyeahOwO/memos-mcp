# 决策记录（Design Decisions）

本文件记录 memos-mcp 项目的关键决策**及其理由**。目的是：以后任何人（包括未来的你）翻一眼就懂“为什么这么定”，不用重新纠结。

> 调研依据：2026-06 对 MCP 生态、同类 Memos MCP 项目、Memos 官方 API 的调研；2026-06-06 产品方向调整为不提供云服务。

---

## 决策 1：语言选 TypeScript

**结论**：用 TypeScript（Node.js）实现。

**理由**：
- TypeScript 是 MCP 的“母语”，官方 SDK（`@modelcontextprotocol/sdk`）成熟，工具链完整。
- `npx` 一行命令运行，适合本地部署和普通用户安装。
- 后续要加本地索引、Docker、CLI 辅助命令时，TS 生态足够覆盖。

**备选（未选）**：Python（FastMCP 写起来快，但分发不如 npx）、Go（单二进制省心，但社区资料和现成例子少）。

---

## 决策 2：不提供云服务，项目定位为本地优先

**结论**：memos-mcp 不再提供作者云端托管服务，也不把公网多用户网关作为产品目标。项目只围绕本地部署设计。

项目支持两种部署形态：

| 部署形态 | 能力 | 数据落点 | 适合场景 |
|---|---|---|---|
| **本地部署：基础检索版** | Memos 原生读写、关键词、时间、标签、附件工具 | 不落本地索引，只转发到用户自己的 Memos | 想快速接入 AI 客户端、低依赖、低维护 |
| **本地部署 + 向量版** | 基础工具 + 本地 JSON 向量索引 + 语义搜索；SQLite/FTS 后续升级 | 索引和向量都在用户本机 | 需要“按意思搜笔记”、可接受本地存储和同步成本 |

**理由**：
- 云服务会引入账号体系、token 保管、用户隔离、合规、安全运维等问题，和当前项目阶段不匹配。
- Memos 本身通常是个人/小团队私有知识库，本地 MCP 更符合隐私和可控性。
- 向量索引会产生存储、算力和数据隔离成本，应该由用户本地承担，而不是作者云端承担。
- 两种本地形态可以用同一套代码和配置开关实现，不需要维护云端/本地两套产品。

---

## 决策 3：鉴权模型只服务本地部署

**结论**：token 只用于本地进程访问用户自己的 Memos 实例，不设计公网多用户 token 网关。

当前凭据来源：

- **stdio**：从环境变量 `MEMOS_ACCESS_TOKEN` 读取，适合 Claude Desktop、Cursor 等本地客户端。
- **本地 HTTP**：从每个请求的 `Authorization: Bearer <token>` 读取，适合支持 Streamable HTTP 的本地 MCP 客户端。

**边界**：
- HTTP 传输保留，但定位是本机/局域网接入，不是作者托管云服务。
- 默认绑定 `127.0.0.1`；不建议绑定公网地址。
- 不做多人共享同一个 memos-mcp 实例的产品承诺。
- 如果同一台机器要服务多个 Memos 账号，推荐运行多个实例，并为向量版配置不同的 `MEMOS_MCP_INDEX_DB`。

---

## 决策 4：传输方式 = 本地 stdio + 本地 Streamable HTTP，SSE 不做

**结论**：
- **stdio**：本地桌面 MCP 客户端的主路径，必做。
- **Streamable HTTP**：本机/局域网 MCP 客户端、Docker、本地服务管理的辅助路径，必做。
- **SSE**：不做。MCP 官方已由 Streamable HTTP 取代 SSE，除非未来出现明确兼容需求，否则不增加维护面。

**理由**：
- 两种标准传输已经覆盖本地使用场景。
- 去掉远程云端诉求后，HTTP 的价值主要是本地服务化、容器化和部分客户端兼容。
- 不支持 SSE 可以减少协议分支和测试负担。

---

## 决策 5：向量能力只作为本地增强版

**结论**：语义搜索和 embedding index 只属于“本地部署 + 向量版”，默认关闭。当前实现使用本地 JSON 向量索引；SQLite 缓存和 FTS 是后续增强。

**理由**：
- 基础检索版应该轻依赖、易安装、易调试。
- 向量版会引入本地数据库、同步状态、embedding 模型/API 配置，需要更明确的用户选择。
- 所有索引数据都应留在用户本机，避免云端存储私人 memo 内容。

**实现方式**：
- 默认 `MEMOS_MCP_ENABLE_SEMANTIC_SEARCH=false`。
- 未开启时不加载向量依赖，不创建索引库。
- 开启时提供 `memos_sync_index`、`memos_index_status`，并让 `memos_search` 默认进入语义模式。
- 单用户本地索引即可；多账号使用通过多个实例/多个 index db 隔离。

---

## 决策 6：先交付基础检索版，再把语义能力作为显式增强

**结论**：第一版先完成基础本地功能；随后语义搜索以可选本地增强方式接入，不改变基础版轻依赖原则。详见 [roadmap.md](./roadmap.md)。

**理由**：
- 基础工具是向量版的地基，包括配置、传输、鉴权、Memos 客户端、归一化、权限网关。
- 基础版主要是“翻译 + 转发”Memos 原生 API，能快速交付可用成果。
- 时间检索、标签、附件等普通工具先补齐，再引入索引和向量复杂度。
- 当前语义搜索实现选择 JSON 索引 + OpenAI-compatible embeddings，避免一开始引入 SQLite、本地模型和大型依赖。

---

## 仍需防御的已知风险

**Memos API 版本兼容**：Memos 升级时改过 API（v0.22 做过大重构，字段改过名；私有 memo 经 API 可见性有已知 issue）。

**对策**：坚持架构文档里的 `NormalizedMemo` 归一化层（把 Memos 返回的数据翻译成统一内部格式，隔离版本漂移），并锁定一个明确的目标版本基线（如 v0.24 / v0.26），不裸对接 `latest`。
