# 决策记录（Design Decisions）

本文件记录 memos-mcp 项目的关键决策**及其理由**。目的是：以后任何人（包括未来的你）翻一眼就懂"为什么这么定"，不用重新纠结。

> 调研依据：2026-06 对 MCP 生态、9+ 个同类 Memos MCP 项目、Memos 官方 API 的调研。

---

## 决策 1：语言选 TypeScript

**结论**：用 TypeScript（Node.js）实现。

**理由**：
- TypeScript 是 MCP 的"母语"，官方 SDK（`@modelcontextprotocol/sdk`）最成熟，工具链最全。
- `npx` 一行命令零安装运行，对不懂代码的用户最友好。
- 将来要做云端托管的 Web 外壳，TS 生态一条龙最顺手。

**备选（未选）**：Python（FastMCP 写起来快，但分发不如 npx）、Go（单二进制省心，但社区资料和现成例子少）。

---

## 决策 2：鉴权照搬 GitHub MCP —— 调用方自带钥匙，服务器不存钥匙

**结论**：每个请求由**调用方**在 HTTP header 自带自己的 Memos 钥匙：

```
Authorization: Bearer memos_pat_xxxxxxxx
```

memos-mcp 服务器本身**不存储任何用户的钥匙**。

**理由**：
- 这是 GitHub 官方 MCP 的做法，被验证可行。
- 它让云端托管版**省掉了整套多用户大工程**——不用做账号系统、不用替用户加密保管钥匙、不用做用户隔离。**钥匙即身份，每个请求天然隔离。**
- Memos 官方原生支持且明确推荐："外部工具用 Personal Access Token，别用浏览器登录态。"（已于 2026-06 核实）

**前提与注意**：
- 云端挂域名**必须 HTTPS**，否则钥匙在网络上裸奔。
- 这个"零保管"只在**无本地索引**时成立。一旦加了本地缓存/向量（第二步），缓存必须按钥匙隔离，否则多用户数据会串号。**所以云端托管版应保持"无索引的轻量代办"形态。**

---

## 决策 3：三种部署模式，向量检索不上云

**结论**：项目支持三种使用模式，用户自选：

| 模式 | 普通功能 | 向量检索 | 适合谁 |
|---|---|---|---|
| **1. 纯云端** | 作者云端 | 无 | 图省事、零安装 |
| **2. 混合** | 作者云端 | 用户本地自建 | 既要方便又要语义搜索 |
| **3. 全本地** | 用户本地 | 用户本地 | 隐私敏感 / 完全自主 |

**理由**：
- 普通功能（写/搜/时间查）很轻，适合放云端共享。
- 向量检索很重（吃算力和存储），**不该由作者云端替所有人承担**——留给用户本地自建，吃他自己的资源。
- 模式 2 不需要"云端和本地打通"的复杂机制：用户只是在 AI 客户端里**同时挂两个 MCP**（一个云端、一个本地只开向量），各管各的。

**实现方式**：**同一套代码 + 一个开关**（`MEMOS_MCP_ENABLE_SEMANTIC_SEARCH`）决定轻/重，不写三套。普通功能模块和向量模块要能"合体也能拆开"。

---

## 决策 4：传输方式 = stdio + Streamable HTTP，SSE 不做

**结论**：
- **stdio**：本地用（Claude Desktop、Cursor 等），必做。
- **Streamable HTTP**：远程 / 云端用，必做。
- **SSE**：已被 MCP 官方废弃（2025 年起），不做（最多作为向后兼容、默认关闭）。

**理由**：2026-06 调研确认，官方规范现在只定义 stdio 和 Streamable HTTP 两种标准传输，SSE 已被 Streamable HTTP 取代。

---

## 决策 5：第一步只做"普通功能模块"

**结论**：第一版（MVP）只做不含向量的普通功能，向量留接口、第二步再做。详见 [roadmap.md](./roadmap.md)。

**理由**：
- 普通功能模块 = 模式 1 的全部 + 模式 3 的一半，是一切的地基。
- 它基本是"翻译 + 转发"的活（Memos 原生 API 已支持写/搜/时间过滤），不复杂、能快速交付可用成果。
- 把"扛不住、数据串号、太复杂"这些麻烦全留在向量那块，第一步完全不碰。

---

## 仍需防御的已知风险

**Memos API 版本兼容**：Memos 升级时改过 API（v0.22 做过大重构，字段改过名；私有 memo 经 API 可见性有已知 issue）。

**对策**：坚持架构文档里的 `NormalizedMemo` 归一化层（把 Memos 返回的数据翻译成统一内部格式，隔离版本漂移），并锁定一个明确的目标版本基线（如 v0.24 / v0.26），不裸对接 `latest`。
